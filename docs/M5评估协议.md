# M5 替代语料主实验协议 v1

配置：[formal_data.yaml](../configs/formal_data.yaml)、[main.yaml](../configs/main.yaml)。沿用 M1～M4 已验证的 SS、LPC、通道、63 维特征、A/B 和指标实现，本轮补齐独立语料分区、多种子训练和 E02～E05 主实验。版本 0.5.0；本协议中的“主实验”指项目固定替代语料子集，不表示完整 TIMIT 或官方 LibriSpeech 榜单复现。

## 1 语料来源与范围

此前用户说明暂无 TIMIT，本轮按方案第 5.1 节采用有明确许可的替代语料：OpenSLR 官方 Mini LibriSpeech SLR31 的 train-clean-5、dev-clean-2，加 SLR12 的 test-clean。许可 CC BY 4.0，英语朗读、分发音频为 16 kHz 单声道 FLAC。保留许可证、README、SPEAKERS.TXT、CHAPTERS.TXT 和选中原始 FLAC。分发 FLAC 为无损格式，但 LibriSpeech 的原始朗读来源不等于 TIMIT 录音条件，不声称原录音链路完全无损。

训练包清点实际仅 28 位说话人，不支持最初草拟的 40 训练/10 验证说话人方案。因此在任何训练/测试评分前，改为独立验证池并固定以下数量。这是元数据可用性调整，不是按效果选数据。

每条源语句时长须至少 3 秒，按 `SHA256(seed|role|identifier)` 排序选说话人、再排序选句，seed=20261018。每句只取一个居中 3 秒片段，记录原始起止采样点；不先挑有语音最多的区间，不按 PESQ、VAD、标签或检测分数选择。F/M 完全来自官方 SPEAKERS.TXT，不推测性别。

所有分区排除 M1～M4 说话人 5703、3436、198。检查 speaker_id、parent_utterance_id、源文件 SHA、源解码 PCM SHA 和准备片段 PCM SHA 不跨区。按整条原语句/说话人组织，任何水印/通道派生物保持原分区。selection_before_audio_processing.jsonl 先保存选样；all/train/validation/test 清单、split_audit 和 freeze.json 冻结其后。可从完整 catalog 和策略重新选样验证。

准备音频为浮点 WAV、16 kHz，输入峰值只降低至不超过 0.5，不抬高小幅信号；保留源文件。固定子集/裁剪降低本机实验量，训练规模仍明显小于论文。正式报告必须保留这一差异，不把 568 个片段写成完整 LibriSpeech。

## 3 共同处理与实验矩阵

每个源片段先计算 SS 与 SS_LPC、0/1/2/3/4/6/8 dB 所有变体的最大峰值，共享一次额外增益，目标 0.90。正负标签、方法和后续通道使用同一参考增益，不能分别归一化/削波。即使 E04/E05 仅使用 1/3 dB，也不从共同控制中移除高强度版本。

频谱、密钥和接收特征沿用 M4：20 ms 周期 Hann、10 ms 帧移，500～3600 Hz 的 63 点，0.5 ms 倒谱截止，已保存 ±1 密钥，WebRTC VAD aggressiveness=2。检测只使用接收文件的完整分析窗与 VAD 交集。相关检测为 float64 匹配特征均值，A/B 输入相同位置的 float32，不额外标准化。

LPC 固定 16 阶、自相关/相对正则 1e-6、逐帧带内中心化、Gaussian sigma=13.5、alpha=0.35。工程假设与论文原文边界沿用 M3，不在测试集重新拟合。

| 实验 | 验证阶段 | 测试阶段 |
| --- | --- | --- |
| E02 LPC 音质 | SS/LPC 全局强度扫描、仅据 NB PESQ 匹配 | 原样应用全网格，报告 NB/WB 和 F/M 分组 |
| E03 LPC 鲁棒性 | 冻结匹配强度、20/15 dB 噪声阈值 | 两方法共享噪声，经 16→8 kHz，1/10/30 帧 EER/FAR/FRR |
| E04 深度降采样 | SS 1 dB、C1，训练/验证 A/B | 同接收文件比较相关/A/B，8 个聚合长度 |
| E05 深度编码 | SS 3 dB、C3，训练/验证 A/B | 8 kHz→真实 Opus 8 kbps，同组比较相关/A/B |

噪声与 Opus 细项沿用 M2，保留包内 FFmpeg 哈希、真实压缩流、编解码输入/输出与容器检查。噪声在 16 kHz 添加后降采样，依据共同未嵌入参考及源 ID/固定种子生成；跨方法和标签共享，不根据待测变体功率分别生成。

## 4 验证选择、训练与测试门

顺序固定：

1. 全语料只做元数据/完整性检查、确定性裁剪与分区冻结。
2. 生成 train/validation 实验音频和特征，不生成测试水印或通道。
3. validation 的两方法全局强度扫描，用距 NB 4.4 的目标距离和配对差≤0.02 选实际测量点；不看 EER，不插值，不逐文件选。保存 quality_selection 与 quality_gate。
4. C1/C3 各训练 A/B×seed 2026/2027/2028，共 12 个主设置。训练仅取 train/main，validation 仅作诊断和阈值估计；训练入口拒绝 test。
5. 保存 12 个第 25 轮主权重、12 个最佳验证 BCE 诊断权重。使用 validation/main 为各条件/检测器/种子/聚合长度计算阈值。
6. 保存 evaluation_gate.json，绑定固定配置、输入清单、12 个主权重、强度选择和阈值 SHA。此后才生成测试实验音频、测试 PESQ 和检测分数。
7. 测试原样应用全局强度和阈值。若测试平均音质差超过 0.02，照实报告，不重新匹配。

测试源音频在数据准备时可被读取以计算格式、哈希与固定裁剪；“门前不处理测试”具体指不做水印/通道、音质选择、模型分数、阈值选择或其他性能反馈。程序应验证该顺序，不能将已看的测试结果重新称为未触及测试。

A/B 架构与 M4 相同，参数 6209/15713，B 卷积后无额外激活。BCEWithLogitsLoss、batch=1024、25 epoch；RMSprop lr=0.001、alpha=0.99、eps=1e-8、momentum/weight_decay=0、centered/foreach=false。CPU 单线程、确定性算法。种子每个设置重置，不调参；主结果均为第 25 轮。

另做一次 C1_A 的训练文件标签打乱控制，种子固定；验证仍用真实标签，仅作为一次诊断，不要求有限样本恰好 50%，不据此改变主结果。控制权重不用于正式测试。

## 5 分数、指标与统计单位

深度聚合为 M=1/2/5/10/15/20/25/30；E03 为 1/10/30。每条收到的 WAV 内按有效帧顺序非重叠分组，尾部不足丢弃；不跨文件。A/B 平均线性 logit，相关检测平均相关分数，不平均 sigmoid。有效帧可能跨 VAD 间隙，M×10 ms 不等于连续观测窗。

所有种子/检测器在同一接收音频上共享 VAD 和 group_definitions。逐帧/组 CSV 用 artifact ID 连接 manifest，避免重复保存几百万份来源字符串；清单完整保留标签、分区、父句、说话人、性别、方法、强度、通道和哈希。

- EER 按既有 tie 处理和 FAR/FRR 交点插值；方向固定为越大越倾向含水印，不按结果反转。
- 另报每条语音首个有效帧组 EER，正/负组数、合格配对语句和说话人数、覆盖与失败数。
- A/B 三种子报告均值和样本标准差（ddof=1），相关检测只算一次，不伪造三个随机样本。
- 阈值来自 validation 的插值 EER 点，测试固定 score>=threshold 判正，直接报 FAR/FRR。插值点的离散 FAR/FRR 不一定相等。
- EER 是每个分数总体上的描述性扫描指标，不冒充固定阈值错误率。相关帧组不当作独立语句，不给帧独立置信区间或零错误率保证。
- 独立上传继续 scores_only/decision=null；当前阈值只绑定此模型、分区和通道，不直接开放任意文件的部署判决。

每个 validation/test 分区从 5 位 F、5 位 M 说话人各取一个固定哈希选定片段，做两类零强度配对控制，经过 C1/C3；不进入梯度训练。正负 PCM 和分数应相同，对应 EER=50%。

## 6 核验与交付

全量核验选中原始/裁剪文件和分区；从源数据重算全部嵌入/共同增益，再从所有接收 WAV 重新提取特征和掩码；实际噪声重新生成核对，所有 Opus 检查结构与哈希。重新加载 12 个主权重，逐行复核全部保存帧分数、共同分组与聚合，再从 CSV 重算 EER、种子统计、校准和固定 FAR/FRR。

种子 2026 的 C1/C3×A/B 四个设置完整重训，比较张量 SHA 和逐轮历史；其余两种子验证保存权重推理，明确不声称 12 个设置均完整重训。PESQ 在分区×性别×方法×强度的全部分层组合取一个固定样例重跑，其余行全量核验输入嵌入 WAV；不把分层重跑说成全部 PESQ 重跑。

独立核验脚本把收到的 WAV、密钥和权重复制到空目录，覆盖全部 12 模型与相关检测；没有原语音/缓存时，命令行分数须与测试 CSV 对应组一致。完整归档恢复后再执行该检查。M1～M4 精简清单/既有标签/归档保持固定，新分支、提交和 `v0.5.0-m5` 附注标签保存本阶段。

失败记录原因及数量，不以 -1/0/最大 PESQ 或相关检测回退伪装成功；测试错误修复须保留失败运行和新 run-id。性能未达到论文时先保留结果，再解释语料、规模、裁剪和工程差异，不凭效果反改测试参数。

## 7 复现命令

```bash
.venv/bin/python scripts/fetch_formal_data.py
.venv/bin/python -m speechwm.cli prepare-formal --config configs/formal_data.yaml
.venv/bin/python -m pytest -q
.venv/bin/python -m speechwm.cli evaluate --config configs/main.yaml --run-id NEW_RUN_ID
.venv/bin/python -m speechwm.cli validate --run-dir outputs/E_M5_librispeech_main_v1/main-v1
.venv/bin/python scripts/verify_main_inference.py --run-dir outputs/E_M5_librispeech_main_v1/main-v1 --output NEW_OUTPUT.json
```

以上 fetch/prepare-formal 适用于尚无冻结清单的首次准备。Git 已包含冻结 manifest 时，新环境应从 M5 ZIP 恢复 data/raw 与 data/processed，不重新执行 prepare-formal；若要重建新数据版本，另设 dataset_id 和目录，不能覆盖旧版本。准备数据和 evaluate 拒绝覆盖现有冻结目录/运行。完整下载脚本先校验已存在缓存，下载只在缺失时进行。依赖沿用 M4，无新增运行库，版本推进为 0.5.0。
